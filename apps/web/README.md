# Citizen Interface

The React application now opens to a national operating-picture prototype with a searchable D01–D20 domain directory. Every domain has at least one small working local action: consent-preference mock, institution/source/indicator registers, service and infrastructure signals, environment observations, specialist aggregates, debate review notes, audit entries, legal-source index, preparedness checklist, treaty index, scenario/budget calculators, and more. Several domains link to dedicated workspaces for debates, specialist capacity, prices, jobs, agriculture, trade chains, tourism, service timing, or the problem-to-project workflow. Domain entries support a local new → review → recorded lifecycle and can be deleted. The earlier problem-to-project flow remains available as its own workspace with guest browsing, optional Keycloak sign-in, problem submission, evidence/options, review, appeals, projects, and milestones.

All country indicators, domain entries, debate arguments/support counts, AI-review labels, jobs, chain data, price amounts, demand curves and related content shown in the operating-picture preview are illustrative fiction. Workspace actions are saved only in this browser's localStorage. No national data source, AI model, specialist register, price service, job feed or supply-chain service is connected. Browser-local demo arguments/supports are not sent to an API. The debate AI panel is a proposed review rubric with prewritten example labels, not model output. These limits are also described in the [operating-picture blueprint](../../docs/system/operating-picture/README.md).

In Vite development mode only, the “Demo cetatean” button opens a local preview with fictional sample data saved in browser storage; it does not authenticate with Keycloak or call the domain APIs. The imported Keycloak example account is `demo.citizen` / `PolisOS-Demo-Only-2026!` and works only when the local Docker services are running.

The interface is Romanian-first and keeps account names and email out of public records. It uses React/TypeScript/Vite (MIT for React; audit exact dependency licenses), OIDC authorization code with PKCE, and REST APIs. The prototype makes no claim of monitoring or controlling current Romanian services. Hosting, moderation, translation, accessibility audits, support and security response are recurring costs. Domain APIs remain replaceable; the interface stores no authoritative domain state.

The distinct “Economia cetățeanului” page is a local household balance canvas: it lets a person edit gross income, benefits, taxes, household size, prices, quantities, diet and selected spending categories; it estimates domestic and external/unknown spending shares and displays optional non-cash public-service values, days off, environment and universal rights separately. Its example values are fictional and its settings stay in browser `localStorage`; it does not call an API or calculate actual Romanian tax, tariffs, entitlements, or population statistics. See the [household balance specification](../../docs/citizens/household-balance/README.md).

The national operating picture now leads with country functions and outcomes, then connects example needs to opt-in local skill matching. The “Simulare de afaceri” module is a local tailoring-shop business planner with editable premises, equipment, payroll, utilities, materials, product prices/volumes, labor capacity, break-even and conditional approval tracking. All scenarios are illustrative; skills and business assumptions stay in browser `localStorage`. There are no real workforce counts, market-price feeds, demand estimates, permit checks or business-registration integrations. See the [national capacity and business feasibility blueprint](../../docs/business-planning/README.md).

In the business planner, each authority area now has a candidate document and question checklist that the user can check off locally after confirming applicability. The same model estimates local versus imported-or-unverified material spending and domestic versus export sales from editable assumptions. It does not assert legal requirements, validate an approval, verify supplier origin or connect to buyers.
