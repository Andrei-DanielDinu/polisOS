## Shared chapter structure

Every domain chapter states: purpose and outcomes; citizen experience and accessibility; roles, authority, and boundaries; workflow and states; observation sources, purpose, cadence, uncertainty, and steward; privacy, retention, and access; measures and feedback; failures, correction, and appeal; integrations and event/API boundaries; delivery stages; stack record; and open decisions.

A domain README is a specification, not proof that a capability exists. It does not imply that an institution has adopted PolisOS or that the system can exercise its legal powers.
